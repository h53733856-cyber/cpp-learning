# C++基础

## 1. 指针

1.1 什么是指针
指针是一种变量类型，他存储的是另一个对象的内存地址

1.2 指针可以修改所指对象
```c
    int a=10;
    int *p=&a;
    *p=20
```
执行之后`a=20`,因为`p`保存的是`a`的地址，`*p`就是访问`a`本身

1.3 指针可以改变指向

1.4 对于传址
`&a`->传给`p`->`p`保存`a`的地址->`*p`找到`a`->`*p=100`->`a=100`

传值引用时，函数操作的是副本，传址引用时，函数可以通过指针解引用访问并修改原对象

1.5 智能指针

1.5.1 悬空指针
```c
int* p = new int(10);
int* q = p;
delete p;
```
上述情况中，`delete p`之后p变成了已经释放的内存，`q`依然保存了已经失效的地址，这个时候`q`就会变成悬空指针（补充：`new`是在动态存储区（堆）申请对象，并返回这块对象的地址，不是把空间给当前变量，而是变量`p`保存了这块空间的地址

1.5.2 引入智能指针
普通指针可以指向对象，但是释放内存需要自己管理，容易出现内存泄漏，悬空指针，重复释放，异常/提前return导致忘记释放，因此引入智能指针，所谓智能指针，本质上还是一个对象，只不过这个对象内部帮你管理一个指针，并在合适的时候自动释放他所管理的内存，就是说普通指针先`new`再`delete`都是自己负责的，但是智能指针希望实现使用之后自动释放。根据所有权，智能指针分为下面三类：

`unique_ptr`
这个类型表示这块资源只有一个主人，常见的写法是`std::unique_ptr<int> p = std::make_unique<int>(10);`，（对应以前`int *p = new int(10)`），可以理解成只有`p`管理这块内存，`p`生命周期结束时，`unique_ptr` 析构，自动释放，他的唯一性体现在，不能被复制，比如已经有了前一句代码之后不能再有`std::unique_ptr<int> q = p;`，因为两个 `unique_ptr` 都会认为自己拥有同一块内存，最终可能对同一块内存执行两次 `delete`

但是如果真的想把所有权交给`q`，就可以使用`std::move`，就是说`std::unique_ptr<int> q = std::move(p);`是可以的，执行之后`p`为空，`q`得到所有权

`*p`访问对象，`p->`访问对象成员
`p.get()`获取它内部管理的普通指针，`q=p.get()`之后`q`仍然不会获得所有权，只是拿到了一个普通指针，是不允许`delete q`的，因为如果此时释放掉，`p` 并不知道对象已经被释放了，它仍然认为自己拥有这个对象，最终析构再次释放就会导致重复释放
`p.reset()`是让`p`放弃他管理的对象，并释放对象，`int* raw = p.release();`表示`p`放弃了所有权，把普通指针交给`raw`，`raw`变成了普通指针，后续要记着`delete raw`

`sharded_ptr`
意思是多个智能指针可以共同拥有这个对象，经过下面这段代码之后：
```c
std::shared_ptr<int> p = std::make_shared<int>(10);
std::shared_ptr<int> q = p;
```
`p`和`q`都拥有了这个对象

对于`shared_ptr`，它内部会维护“引用计数”，刚开始`std::shared_ptr<int> p =std::make_shared<int>(10);`使引用计数等于1，在`std::shared_ptr<int> q = p;`的时候，引用计数等于2，当`q`消失的时候，引用计数从2变成1，但是对象不能释放，因为`p`还拥有他，最后`p`消失的时候，引用计数从1变成0，此时没有任何`shared_ptr`拥有对象，会自动释放

用`p.use_count()`来查看引用计数，`p.reset()`并不一定会释放

`weak_ptr`
弱引用，`weak_ptr`不拥有对象，例如`shared_ptr p`拥有对象时，它具有所有权，但是`weak_ptr`只是观察者
```c
auto p = std::make_shared<int>(10);
std::weak_ptr<int> w = p;
```
`w`并不会让`shared_ptr`的引用计数增加

```c
A shared_ptr → B
B shared_ptr → A
```
上面这段代码中，`A`拥有`B`，`B`拥有`A`，结果是两者的引用计数都等于1，互相拥有，引用计数永远不会变成0，内存无法释放，这就会导致“循环引用”，解决方法是
```c
A shared_ptr → B
B weak_ptr  → A
```
`A` 拥有 `B`，`B` 只是观察 `A`，就不会因为 `B` 观察 `A` 而阻止 `A` 被释放

但是不可以`*w`，因为`w`不保证对象还存在，可以使用的是`w.lock()`，意思是“这个对象现在还活着吗？如果还活着，给我一个 shared_ptr。”，就是说如果对象还存在的话，就得到`shared_ptr`指向对象，如果不存在的话就得到空的`shared_ptr`，例如`auto q = w.lock();`，需要注意的是这样就会让引用计数+1



关于智能指针的例子
```c
std::unique_ptr<int> p = std::make_unique<int>(10);
*p = 20;
std::cout << *p << std::endl;
```
Q1:`*p = 20` 为什么能够修改 `unique_ptr` 管理的 `int`
A:`p` 管理的是一个 `int` 对象，而 `*p` 就是访问这个 `int` 对象本身，所以可以像普通 `int` 一样修改它

Q2:如果换成
```c
std::unique_ptr<int> p = std::make_unique<int>(10);
std::cout << p << std::endl;
```
能否正常输出
A:`p` 不是普通的地址变量，它是一个 `unique_ptr<int>` 对象，`unique_ptr` 没有提供适合这种 `cout << p` 的输出方式，如果想输出里面的`int`，可以`cout << *p;`，如果想获得他管理的普通指针地址，可以`cout << p.get();`

Q3:考虑下面这段代码：
```c
void test()
{
    auto p = std::make_unique<int>(10);
    int* q = p.get();
    std::cout << *q << std::endl;
    p.reset();
    std::cout << *q << std::endl;
}
```
执行`p.set()`之后`p`和`q`分别是什么状态
A:执行之后，`p`是空的`unique_ptr`，`q`不是空指针，而是悬空指针


## 2. 引用

2.1 什么是引用
引用可以理解为一个已有对象的别名，引用不能重新绑定

```c
int a = 10;
int b = 20;

int& r = a;

r = b;
```
执行之后，两个变量都是20，`r=b`不是`让r从引用a变成引用b`，而是`把b的值赋给r所引用的对象，也就是a`

| 指针 | 引用 |
| :保存地址: | :直接代表已有对象: |
| :可以改变指向: | :初始化之后不能重新绑定: |
| :可以是nullptr: | :正常引用必须绑定对象: |
| :调用函数时传的是地址: | :调用函数时直接传对象: |

引用非常适合用来让函数直接操作原对象，可以节省开销

## 3. const

### 核心原则：看`const`修饰的是谁

3.1 `const`变量
```c
const int a = 10;
a = 20; 
```
`a`是`const`，不能修改

3.2 `const`+指针（`const int*`）
`const int* p`表示不能通过 p 修改它指向的对象，但 p 本身可以改变指向
```c
int a = 10;
int b = 20;

const int* p = &a;

*p = 30;  // 不可以
p = &b;   // 可以
```
3.3 `int* const p`
`int* const p = &a;`表示 p 本身不能改变指向，但可以通过 p 修改所指对象
```c
int a = 10;
int b = 20;

int* const p = &a;

*p = 30;  // 可以
p = &b;   // 不可以
```

3.4 `const int* const p`
表示既不能通过 p 修改对象，也不能改变 p 的指向

3.5 `const`+引用（`const int&`）
```c
int a = 10;
const int& r = a;
```
表示`r`是`a`的只读别名，不能通过修改`r`修改`a`，但是`a`本身是可以被修改的
```c
r = 20;  // 不可以
a = 20;  // 可以
```

3.6 `const`对象不能绑定到普通引用
```c
const int a = 10;
int& r = a; 
```
因为普通引用`int& r`理论上允许`r=20`，这样就相当于绕过`a`的`const`限制，所以应该`const int& r = a;`

3.7 `const`引用很常见
`void print(const std::string& str)`可以避免复制整个对象，减少不必要的开销，又能保证函数不会通过`str`修改原对象

## 9. 拷贝构造

9.1概念
用一个已经存在的对象，新建另一个对象时调用
```c
class Student {
public:
    Student(int a) {
        age = a;
    }

    Student(const Student& other) {
        age = other.age;
    }

private:
    int age;
};
```
然后
```c
Student s1(20);
Student s2(s1);
```
第一句是用普通构造函数创建对象，第二句就是用一个已经存在的对象创建新的对象

## 10. 拷贝赋值

10.1
```c
Student s1(20);
Student s2(30);
s2 = s1;
```
这里不是创建`s2`，因为`Student s2(30); `的时候，`s2`已经存在了，现在只是把 `s1` 的内容赋值给已经存在的 `s2`，这就是拷贝赋值

拷贝构造是`s1 -> 复制 ─> 新对象 s2`,拷贝赋值是`已有s2 , s1 ─> 赋值 ─> 已有的 s2`

10.2
浅拷贝->两个对象指向同一资源->一个释放->另一个还以为资源属于自己->重复释放 / 悬空指针

10.3
深拷贝：不复制指针本身，而是复制指针指向的资源，两个对象拥有自己的内存

10.4 RAII
让对象负责资源的生命周期————构造函数->获得资源->使用资源->析构函数->释放资源

## 11. virtual和多态

11.1 概念
多态就是：同一个接口，不同对象执行不同实现，c++多态分两种
静态多态（编译期）：函数重载、模板。编译阶段就确定调用哪个函数
动态多态（运行期）：虚函数实现，运行时才确定调用哪个版本

父类写虚函数 virtual void func，子类可以重新写这个func，改成自己的实现，父类指针指向子类对象，就会触发多态

因此，触发动态多态的三个必要条件：
1. 存在**继承关系**
2. 基类函数用`virtual`声明为虚函数，派生类重写 (override) 该函数
3. **基类指针 / 引用**指向派生类对象，调用虚函数
